# SOL Predictor

Прогноз **размаха движения** SOL на 1 ч, 4 ч, 12 ч и 1 день: будет тихо, как обычно или буря, и в каком коридоре пройдёт цена. Направление модель не предсказывает: первая версия это пробовала, и на истории направление угадывалось почти как монетка (53%), а после комиссии давало минус. Размах предсказуем по-настоящему.

Результат на 2025 → ноябрь 2026, которые модель не видела (горизонт 4 ч):
- ошибка прогноза на треть меньше, чем у «как обычно за последние 30 дней» (R² = 0.33 по логарифму размаха);
- коридор 80% накрывает реальный размах в 78% случаев;
- там, где модель ждала самые сильные движения, они были в 2.8 раза больше, чем там, где она ждала тишину.

Только бесплатные данные, без сервера: GitHub Actions считает прогноз каждый час, GitHub Pages показывает Telegram Mini App, бот предупреждает о буре. **Не финансовый совет.**

## Схемы

| | Схема | Данные |
|---|---|---|
| V | Собственная волатильность SOL: час, сутки, неделя, месяц (модель HAR), объём | спот-свечи Binance |
| T | Время суток и выходные | календарь |
| E | Волатильность BTC | спот-свечи |
| A | Сила и знак недавнего движения, просадка | спот-свечи |
| B, C | Открытый интерес, long/short, премия/funding | архивы фьючерсов Binance (с задержкой 30 ч) |
| F, G | Стейблкоины на Solana, страх и жадность | DefiLlama, alternative.me |

## Команды

```bash
pip install -r requirements.txt
python test_backtest.py      # проверка на утечку будущего: на случайном блуждании модель не должна ничего находить
python backtest.py           # walk-forward: выбор на 2023–2024, честный результат на 2025→сейчас, пишет model.json
python predict.py --dry-run  # текущий прогноз в docs/data.json, без Telegram
```

## Запуск в Telegram (один раз)

1. Создать **публичный** репозиторий на GitHub и запушить в него эту папку.
2. Settings → Pages → Source: *Deploy from a branch*, ветка `main`, папка `/docs`. Ссылка будет вида `https://<логин>.github.io/<репо>/`.
3. В Telegram у @BotFather: `/newbot` и сохранить токен. Затем `/setmenubutton`: выбрать бота, вставить ссылку из шага 2, текст «Прогноз».
4. Написать своему боту любое сообщение и открыть `https://api.telegram.org/bot<ТОКЕН>/getUpdates`. Число в `"chat":{"id":...}` — это chat id.
5. В репозитории Settings → Secrets and variables → Actions:
   - Secrets: `TG_TOKEN` (токен), `TG_CHAT` (chat id);
   - Variables: `APP_URL` (ссылка из шага 2).
6. Actions → `predict` → *Run workflow*. Дальше всё работает само, каждый час.

Раз в месяц-два полезно заново запускать `python backtest.py` локально и коммитить новый `model.json`.

## Сбор ликвидаций

Ликвидаций нет в бесплатной истории, поэтому их приходится записывать самим, начиная с сегодняшнего дня. Это нужно для честной проверки флеш-отскока (подробности в `research/LOG.md`).

```bash
python liq/collect.py    # пишет data/liq/: ликвидации Binance, Bybit, OKX по всем USDT-контрактам + OI и funding раз в минуту
python liq/summary.py    # что уже собрано: покрытие, объёмы, крупнейшие всплески
```

Сбор идёт на этом компьютере: файл `sol-liq-collector.cmd` в папке автозагрузки Windows запускает сборщик в фоне (`pythonw`, без окна) при каждом входе. Лог — `data/liq/collector.log`. Второй экземпляр не запустится. Пока компьютер выключен, Binance и Bybit не пишутся, а OKX при каждом старте и потом каждые 6 часов дозагружает последние ~24 часа по SOL, BTC и ETH, поэтому при запуске раз в день дыр по OKX почти нет. Пропуски видны в `up_*.csv`. Остановить: завершить процесс `pythonw.exe` в диспетчере задач; убрать автозапуск: удалить этот файл из `shell:startup`. Если появится сервер, работающий 24/7: `bash liq/server/deploy.sh пользователь@IP КЛЮЧ` ставит сборщик туда как сервис. Binance отдаёт не больше одной ликвидации в секунду по монете, поэтому его объёмы — нижняя оценка.
